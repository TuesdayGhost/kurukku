```
このプロジェクトは、認知症の父と暮らす家族の「今日は何日？」「誰がどこにいる？」という毎日の確かめと、毎朝のホワイトボードの書き直しを、「忘れても、見れば今日が分かる」暮らしに変える、電子伝書鳩のWebアプリです。

僕は毎朝、ホワイトボードに家族の予定を書いていました。天気を調べ、予定を聞いて書き出す。新聞を置かれると消えて、書き直し。フルタイムで働く僕には、小さくない負担でした。

くるっくーは、父の部屋のタブレットに日付・天気・今日の予定・家族の知らせを大きな文字で、いつも同じ場所に出します。予定の時間には鳩が鳴いて「お父さん、6時半から夕ごはんです」と読み上げます。家族は外出先のスマホから「12時に戻ります」と送るだけです。父が家に戻らないときは、ボタン1つで顔写真・身長・よく着る服をまとめたレスキューカードを出せます。月末には、Claude がその月の記録から家庭新聞「鳩月報」を書きます。

僕のアプリは、決して華やかなものではありません。目指したのは、日々忘れていく父が、その瞬間を穏やかに過ごせるように、ほんの少しだけ支える道具です。
```

## Claude をどう使いましたか

**開発**：プログラミングはほぼ初心者です。コード・データベース・テストのすべてを Claude Code と会話で作りました。事前に書いた仕様書から始め、仕様と決定ログ（理由つき）を Claude Code と更新し続けました。Supabase は MCP サーバーから操作し、権限は一時的なアカウントでテストして取り消しています。UI は、WCAG 2.2・JIS X 8341-3・W3C COGA を根拠にした自作の Skill（kurukku-ui-review）で見直し、文字の大きさと情報量を変えて実機で確かめました。別の Claude のインタビューで実体験を仕様にし、別のモデルのレビューで見つかった権限・費用の問題も直しています。

**アプリの中**：鳩月報の見出しと記事を、Edge Function から Claude（structured outputs）で書いています。数字はデータベースが数え、Claude には推測させません。本人情報やレスキューカードの内容は渡さず、APIキーはサーバー側だけにあります。

### 開発中に一番詰まった場面（3000字以内）

**① 何を作ろうとしていましたか？**
父の部屋のタブレットで、予定の時間に鳴る「お知らせの音」です。通知音のほかに、家族が「鳩時計」と「振り子時計」を選べるようにしたいと考えていました。音は、父が毎日何度も聞くものです。

**② Claude にどのように指示しましたか？**
「お知らせの音を、通知音・鳩時計・振り子時計の3種類から選べるようにしたい」と頼みました。外部の音源は権利の確認が必要なので、ブラウザの中で音を合成して作る方針になりました。

**③ 何が起きましたか？**
Claude Code は、ブラウザの音の機能（Web Audio）で、鳩時計の「ポッ・ポー」と振り子時計の「ボーン」を合成しました。コードは動き、テストも通りました。でも、実機で聞いた鳩時計は幽霊のような声で、振り子時計はお寺の大きな鐘のようでした。

**④ 期待していた結果と何が違いましたか？**
期待していたのは、家にある時計のような、やさしくて生活になじむ音です。Claude Code の作業環境には音を聞く手段がないので、「音が鳴ること」までは確かめられても、「どう聞こえるか」は確かめられませんでした。毎日何度も聞く人にとって、そこがいちばん大事なところでした。

**⑤ どのように対処しましたか？**
合成した鳩時計と振り子時計は使わないと決め、決定ログに理由（「幽霊みたい」「お寺の鐘みたい」）を残しました。そのうえで、私が Python で音のファイルを作り、Claude Code がそれを読み込んで鳴らす作りに変えました。外部の素材を使わないので、権利の心配もありません。実機で聞き直して、「音もいい」と思えるところまで来ました。

この経験から、音や見た目のように「人が感じるもの」は、Claude に作ってもらったあと、必ず実機で自分の目と耳で確かめる、という進め方にしました。Claude Code も、確かめたこと（テスト）と、実機でまだ確かめていないことを分けて記録してくれたので、何を自分で見ればいいかが分かりやすかったです。

**1. 日本語や日本の業務で使う立場から気づいた欠点と利点（具体例）**
- 利点：「やさしい日本語で、短く」と頼むと、専門用語を言いかえて説明してくれました。Git をよく知らない私にも、ファイルを直接送ってくれたり、手順を1つずつ書いてくれたりしました。家族の呼び名（「お父さん」）、午前・午後の時計、ホワイトボードの「9:00」の書き方など、日本の家庭の細かい習慣にも合わせて作れました
- 欠点：確かめないまま答えることがありました。たとえば「アプリで名前を直せます」と言ったのに、実際にはその画面がなかったことや、「Google ドライブにつなげない」と言ったあとで、試したらつながったことです。どちらも私が聞き返して分かりました。また、答えが長くなりがちで、スマホで読むと大変なときがありました

**2. 他の AI ツールと比べて劣る点と優れる点**
（例）提出前に、別の AI（GPT）にも読み取りだけのレビューを頼みました。Claude のレビューのあとでしたが、アカウントを切り替えたときに前の家のデータが残る問題など、3つの指摘が見つかり、どれも Claude Code が確かめたうえで直しました。1つのモデルだけに頼らず、別の目を入れるのが大事だと感じました。Claude の優れている点は、指摘をうのみにせず、コードと本番の設定で確かめてから直し、理由を記録に残してくれたことです。（比べていなければ「比較なし」）

**3. 一つだけ直せるとしたら何か、その改善で何が作れるようになるか**
（例）クラウドの Claude Code から、iPhone の Safari や実際の端末で、画面と音を確かめられるようになってほしいです。今回は Safari の表示や音の癖を、私が実機で試して報告するしかありませんでした。それができれば、プログラミングに詳しくない人でも、高齢の家族が使う端末に合わせたアプリを、もっと安心して作れるようになると思います。
