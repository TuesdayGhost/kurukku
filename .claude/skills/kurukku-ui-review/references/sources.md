## A. 規格要件 [R]

### WCAG 2.2 — Web Content Accessibility Guidelines 2.2 ✅
- 発行: W3C 勧告（2023-10 初版、以後更新版あり）
- URL: https://www.w3.org/TR/WCAG22/
- 解説（Understanding）: https://www.w3.org/WAI/WCAG22/Understanding/
- 日本語訳（WAIC、2026年に全面見直し）: https://waic.jp/translations/WCAG22/
- 位置づけ: ISO/IEC 40500:2025 は 2023年10月版の WCAG 2.2 と同一内容。
- **達成基準の条件・例外は Understanding で確かめてから書く**（SKILL 1章）。このSkillで読み合わせたもの（2026-11-03）:
  - 1.4.2 音声の制御: https://www.w3.org/WAI/WCAG22/Understanding/audio-control.html — 3秒を超える自動再生に、一時停止・停止か、システム音量と独立した音量調整。システム音量を下げることは停止に当たらない。自動再生そのものは勧めていない
  - 2.2.1 タイミング調整可能: https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html — 解除／10倍以上の調整／20秒以上の猶予での延長（10回以上）のどれか、または例外（リアルタイム・不可欠・20時間超）。キオスクの無操作時の扱いに触れている
  - 2.2.2 一時停止、停止、非表示: https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html — 動き（5秒超・並行表示）と自動更新（並行表示）に、止める等の仕組み。禁止ではない。天気・ニュースを自動更新の例に挙げる。時計は個別に論じていない
  - 3.2.5 要求による変化: https://www.w3.org/WAI/WCAG22/Understanding/change-on-request.html — 利用者の要求によるか、変化を無効にする仕組みがあれば満たす。内容の大幅な組み替えはコンテキストの変化に含まれる
  - 4.1.3 状態メッセージ: https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html — 属性の有無ではなく、メッセージが支援技術に伝わるかを見る

### JIS X 8341-3:2016 ✅（状況は二次情報で確認）
- 名称: 高齢者・障害者等配慮設計指針―情報通信における機器，ソフトウェア及びサービス―第3部：ウェブコンテンツ
- 内容: WCAG 2.0（= ISO/IEC 40500:2012）と一致。達成基準 61、A＋AA は 38。
- 状況: 2020年・2025年の定期見直しで「確認」され有効。WAIC が 2025年10月に改正原案作成委員会を発足し、ISO/IEC 40500:2025 との一致規格とする方針。発行時期は情報源により「2026年度中」〜「2027〜2028年」と幅がある。
- WAIC 発足のお知らせ: https://waic.jp/news/20251113/
- 実務上の扱い: 番号は WCAG と共通。WCAG 2.1／2.2 追加分（下表）は**現行 JIS には無い**。

## B. 補助的推奨 [G]

### W3C COGA: Making Content Usable for People with Cognitive and Learning Disabilities ✅
- 版: W3C Working Group Note, 2021-04-29
- URL: https://www.w3.org/TR/coga-usable/
- 位置づけ: WCAG 2.2 を超える補足ガイダンス。WCAG 適合には不要と明記。健康・安全・介護などの文脈で特に価値があるとされる。加齢に伴う物忘れ（age related forgetfulness）や軽度認知障害のペルソナを含む。
- 版の注意: 第2版を作業中（公開時期未確認）。改訂が出たら番号が変わる可能性あり。

### W3C WAI: Older Users and Web Accessibility ✅
- URL: https://www.w3.org/WAI/older-users/
- 要点: WAI-AGE の調査で、既存の WAI 指針が高齢利用者のニーズの大部分をカバーすると結論。一方、文献レビューでは情報過多が最も多く挙がった課題の一つ。
- 文献の多くが 2008〜2010 年頃のもの。端末事情が古い点に注意。

### W3C: Requirements for Japanese Text Layout（JLReq, 日本語組版処理の要件） ✅
- 版: W3C Working Group Note, 2020-08-11（保守版）
- URL: https://www.w3.org/TR/jlreq/ （日本語版あり: https://www.w3.org/TR/jlreq/?lang=ja ）
- 位置づけ: JIS X 4051 を主な基盤とする和文組版の要件。アクセシビリティ規格ではなく、**組版の正しさ・美しさの根拠**として使う。版面設計（行長、行間、見出し、図版配置）を含む。
- 行間の目安などの数値は、引用する前に原文の該当節を確認すること（要原文確認）。

### JIS S 0032:2003（参照候補・保留。必須の手順に入れない） 高齢者・障害者配慮設計指針―視覚表示物―日本語文字の最小可読文字サイズ推定方法 ⚠
- 内容: 年齢・視距離・輝度などの条件から、日本語1文字の最小可読サイズを推定する方法。
- 状況: 有償規格。原文未入手のため、数表・係数はこのSkillに書かない。入手したら `screens.md` の文字サイズ計算に組み込む。
- 注意: 「最小可読」は「読める下限」であり、「楽に何度も読める大きさ」ではない。採用値は下限より十分大きくする [H]。

### JIS S 0033:2006 高齢者・障害者配慮設計指針―視覚表示物―年齢を考慮した基本色領域に基づく色の組合せ方法 ⚠
- 内容: 年齢による色の見え方の変化を考慮した、識別しやすい色の組合せ方法。
- 状況: 有償規格。原文未入手。2006年以降の改正有無は未確認。
- 使い方: 色で区別する箇所（家族ごとの色分けなど）を設計するときの参照候補。WCAG のコントラスト比は「明るさの差」しか見ないので、色相の区別はこちらが補う。

## C. 範囲外にしたもの（理由）
- 各OSの HIG（Apple 44pt、Material 48dp 等）: 実装時の参考にはするが、根拠ラベルは [G] 扱いで、深追いしない。
- 医療・認知症ケアの臨床文献: 今回の実装判断に必要な範囲を超えるため。必要になったら Astra と相談。
